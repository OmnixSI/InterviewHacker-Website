## 2. 四条路线的实质比较

下表是源码和内容结构所支持的设计判断，不是评委预测分数，也不是已测得的转化排名；移动端代码有适配不等于已完成本次实机验证。

| 路线 | 视觉与奖项潜力 | 产品理解与行动 | 交互与移动端代价 |
| --- | --- | --- | --- |
| Classic（仓库 slug 为 `classic`） | 金属设备、连续交接、明暗主题建立专业感；独特识别弱于 Turn | 六步工作链路易理解，适合吸收其组织秩序 | 设备外框、磁吸滚动和大场景在小屏上占据宝贵空间 |
| 原版 Final | 纸色、定制手写、水面和颗粒边缘已有连贯语言 | 有完整面试演示，但“时刻”与诗性间奏拉长解释路径 | 固定段落及自动演示较多；手机将窗口改为 4:5、12px，仍需检查细字阅读 |
| Final v2 / PR #4 | 沿用 Final 美术；纸与墨窗口、手写批注更贴近产品 | “一场会议一页”与会议类型、系列、资料、改写、纪要形成最完整的产品解释 | 桌面七步固定导览，小屏窗口仍固定；交互丰富，但长流程和控件密度需要取舍 |
| Turn | 声弦、滚动时钟、动态纸色、手写与合成声音构成最鲜明的概念 | 一天中的对话有情绪，但不展示软件窗口，首次访客较难形成具体使用预期 | 默认静音且有键盘、暂停、降级路径；长篇多场景和多循环增加移动端验证成本 |

CSSDA 官方评价包括 UI、UX、Innovation。WOTD 通常需评委平均分超过 8.00 才进入考虑，仍受参赛质量影响；公众分类奖另有投票制度。因此，效果更密集不自动意味着获奖机会更高，软件窗口也不妨碍设计表现力。

## 3. 推荐：一个主产品入口，一个完整体验作品

**主推 Signature 作为产品入口，Turn 保留为独立体验作品。** 新版本吸收 Classic 的秩序、Final 的纸墨与手写、v2 的产品证明、Turn 的声音辨识。统一依据是“对话中的上下文如何变成下一句和下一步”：同一个可操作会话既是视觉主体，也是产品证据。不是把 Turn 首页与 Final 首页首尾硬拼。

本次先在 `/signature/` 与 `/signature/en/` 交付可审查页面，根路径仍保持现有画廊，`/compare/` 继续服务评审。是否把未来独立官网域名或根入口指向 Signature，属于另一次明确的上线选择。

当前源码中的取舍：

1. 首屏同时交代产品用途、试用阶段、等待名单入口与可操作窗口，访客不必走完动画才能理解。窗口中的内容是按已核实能力编排的**交互示例**，不能声称它是软件截图或实时 AI 输出。
2. 会前、会中、会后三个阶段共用一个窗口；工作会议、面试练习、学术讨论三组示例可切换。改写、只记录、纪要原话与手机伴侣都有相应状态变化，深度说明补充信息。
3. 暖纸、深梅色手机段与柔粉纸收尾组织阅读节奏，手写做少量边注。声弦与说话状态呼应，声音主动开启，关闭声音仍能完整理解；保留原生滚动。
4. 小屏重排窗口内容，优先对话、建议和行动；保留可读字号、明确触控目标、键盘路径、暂停、减少动态效果和无脚本阅读。
5. 等待名单直接展示，邮箱必填，称呼和用途可选。后台保留真实空值与页面来源，只有服务端确认后才显示成功；预览环境应明确无法提交，不能伪造入列。

若这一融合版本在细节、性能与可访问性上完成得足够好，它也可以作为参赛候选。Turn 不必成为唯一参赛入口，Final v2 则保留为产品交互的重要设计来源。

## 4. 合并与部署前的必要条件

- **内容真实性**：手机展示、转写、资料使用与纪要能力要对齐产品资料；不添加无法检测、响应速度、准确率、客户数量等未经证实的承诺。当前采用真实产品布局与功能映射的交互示意，实际软件录屏及逐状态比对仍待完成，不能称为已经核验的实机画面。
- **交付闭环**：确认部署环境有正确 SMTP 配置，并由维护者进行一次获授权的真实收件验证。纯函数测试通过仅证明校验、组信和响应逻辑；不证明邮件已送达。现有限流按暖实例工作，也不应宣传为持久的全局防滥用能力。
- **源文件一致性**：冲突解决后重建双语页面、资源哈希、字体子集、风格登记与 README；预览图必须来自浏览器中的实际页面。执行仓库要求的 `npm run check`、`npm run build` 及等待名单测试。
- **浏览器验收**：检查窄屏、触屏、键盘、深浅环境、暂停与减少动态效果、无脚本、画布不可用、表单失败和重试。本次实际覆盖和未覆盖的项目见验收记录，不能把桌面浏览器内的窄视口等同于真机测试。
- **正式发布**：按 `AGENTS.md`，发布到现有 Vercel 正式项目需要维护者授权。批准前提交可审查改动与预览；发布后核对实际部署 ID、源提交、状态及目标 URL，不能以合并成功代替上线确认。

[验收记录](./SIGNATURE-VALIDATION.md) 将静态检查 / 构建、浏览器覆盖、CI、预览部署、正式部署分开；实际软件录屏比对和 SMTP 真实投递验收目前仍待完成。

没有真实访客实验，不能宣称 Signature 已提升转化。后续应比较有效访问到服务端确认申请的完成率，按来源和设备区分；拨弦次数与停留时间只能辅助解释。
