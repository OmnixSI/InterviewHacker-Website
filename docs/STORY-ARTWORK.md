# Story 产品展示

`/story/` 仍是同一套风格的固定入口，不作为新风格登记。按用户要求，展示图及前台正文不叠加“合成 / 示意”标签；制作来源与功能映射记录在本文。

## 制作来源

`scripts/story-screens.mjs` 以 `public/story/assets/ih/` 中的真实软件截图为版式依据（顶栏四页导航、场景与音频来源选择、识别状态行、问题条、加粗要点的建议回答、一键调整与输入栏），重绘为推广用矢量界面，并非逐像素截屏。每个画面填入一个具体、可信的使用情境：

| 画面 key | 情境 | 体现的软件能力 |
| --- | --- | --- |
| conversation | 字节后端二面：从订单系统库存扣减追问到“删除缓存失败怎么办” | 双路识别、回声忽略与“是我说的”、问题类型、流式回答、一键调整、回答记录 |
| context | 同一场二面：“缓存方案上线效果怎么样” | 按问题检索简历 / 题库 / 置顶经验并标注来源，不把全部资料塞入上下文 |
| workspace | 场景页：字节跳动 · 抖音电商后端岗的面试信息与 4 份资料 | 场景分区、模式字段、资料分类 |
| materials | 资料转 Markdown 与 SKILL.md | 批量导入自动归类、本机解析、场景技能 |
| review | 记录页：二面问题清单、我的回答要点与复盘建议 | 搜索筛选、摘要 / 问题 / 转录 / 提词、并入经验库 |
| prompter | 视频面试中放在摄像头下方的悬浮提词器 | 翻页、字号、鼠标穿透时按钮仍可点 |
| phone / devices | 手机伴侣显示当前追问与回答 | 同一 Wi-Fi 查看并遥控 |
| lecture | 组会 · Mamba 论文精读：导师追问“参数随输入变化为什么还能并行训练” | 讲稿跟随当前幻灯片、要点打勾、过渡句、可能被问 |
| meeting | 华东代理商年度续约：对方要求单价再降 8 个点 | 场景底线参与回答、实时纪要（决定 / 待办 / 分歧） |
| course | 操作系统网课：“TLB 未命中时硬件和操作系统分别做什么” | 课件页对齐、引用课件页码与笔记 |
| privacy | 设置 → 数据 | 本机保存、生成回答时发送的内容、按需开启的服务、备份 |

技术问答经过核对：Cache Aside、重试队列 + Canal 订阅 binlog、延迟双删的取舍；Mamba 的并行扫描、核融合与重计算（显存与 FlashAttention 同量级，出自原论文）；TLB 未命中由 MMU 查页表、页表项无效才触发缺页。简历中的 P99、QPS、期望薪资等属于示例用户自己的资料，不是产品性能。画面不出现识别速度、首字耗时或准确率数字。

12 组界面均有浅色和深色版本，桌面画面共用同一金属屏幕外框与显示区域几何。

## 页面映射

| 页面区块 | 画面 |
| --- | --- |
| 首屏设备 | conversation |
| 核心能力（文字与吸顶设备同序） | conversation → workspace → devices → materials → review |
| 产品优势卡片 | context、phone、prompter |
| 使用场景四个标签 | conversation、lecture、meeting、course |

`npm run check` 校验以上顺序、深浅主题配对，以及生成器输出与仓库文件一致。

## 实时演示

“实时演示”是 HTML 构建的助手窗口，由 `public/story/scripts/demo.js` 播放固定脚本：字节后端二面中“订单系统库存怎么扣 → 缓存一致性追问 → 回声被忽略 → 一键改为更简短”。不访问麦克风、模型、网络或遥测；可暂停，减少动态效果时显示静态最终状态。

## 更新流程

1. 编辑生成器中的具体画面；问题、回答、文件名和来源一起改，不只换标题。
2. `npm run screens:build` 生成 `public/story/assets/product-scenes/`。
3. 在真实浏览器中检查浅色、深色、桌面和窄屏，确认没有文字溢出或错误画面。
4. 更新首页与画廊截图，执行 `npm run docs:sync`、`npm run check`、`npm run build`。
